# Account Intelligence Tool

> Hundreds of call transcripts. Which accounts need attention right now?
>
> Account Intelligence Tool reads call transcript `.md` files and produces structured JSON — key insights, risks, opportunities, sentiment, action items, and a health score — so you can scan your full call library in seconds instead of hours.

## Prerequisites

- **Python 3.10+**
- **LM Studio** running locally with a model loaded (tested with Qwen3.5 9B — free, no account required)
- Transcript `.md` files to analyse

## Quick start

```bash
pip install openai anthropic python-dotenv
mkdir raw_transcripts
# Add transcript .md files to raw_transcripts/
# See raw_transcripts/example_transcript.md for the expected format
python transcript_analyst.py --self-name "Your Name"
```

Per-file JSON appears in `output/`. No API keys needed for the default path.

The tool determines who each call was with by removing your name (and other internal team members) from the participant list. See the [Configuration files](#configuration-files) section to set this up for your team.

## What to expect

Each file shows a live timer during LLM inference so you always know the tool is working:

```
[1/6] call_1.md
      Analysing... (5s)    ← updates every second
      Analysing... done (42s)
      -> ./output/call_1.json  health: 7/10
```

Already-processed files are skipped automatically. Use `--force` to re-process:

```
Transcripts: 5 found in 'raw_transcripts'
             2 new, 3 already processed (--force to re-process)
```

Health scores (1-10, generated by the LLM) are displayed inline. Scores below 5 are flagged:

```
      -> ./output/call_2.json  health: 4/10  ! low
```

Errors map to the most probable cause with a tip:

```
[3/6] call_3.md
      Analysing... x LM Studio not responding (localhost:1234)
      Tip: check LM Studio is running and a model is loaded
```

Local reasoning models (e.g., Qwen3.5 9B) take 1-3 minutes per transcript depending on your hardware. The timeout is configurable with `--timeout` (default 300s). The Claude API responds in seconds.

## Usage

### Default — local LM Studio

```bash
# Process all .md files in raw_transcripts/
python transcript_analyst.py

# Custom input/output directories
python transcript_analyst.py --input-dir ./calls --output-dir ./analysis

# Include full transcript text (default: condensed)
python transcript_analyst.py --full-transcripts

# Skip aggregate report (generated by default)
python transcript_analyst.py --no-aggregate

# Re-process all transcripts (ignore existing output)
python transcript_analyst.py --force

# Process a single file (useful for retrying failures)
python transcript_analyst.py --file ./raw_transcripts/call_3.md

# Pass your name(s) so _account_name reflects who you spoke with
python transcript_analyst.py --self-name "Marck" --self-name "Marck Ernest"
```

### Claude API — optional upgrade

Create a `.env` file in the project root:

```
ANTHROPIC_API_KEY=sk-ant-...
```

```bash
# Use Claude instead of local LM Studio
python transcript_analyst.py --use-claude

# Use Claude with a specific model
python transcript_analyst.py --use-claude --claude-model claude-sonnet-4-20250514
```

### All options

| Flag | Default | Description |
|---|---|---|
| `--file` | (none) | Process a single transcript file (overrides `--input-dir`) |
| `--input-dir` | `./raw_transcripts` | Directory with transcript `.md` files |
| `--output-dir` | `./output` | Directory for output JSON files |
| `--no-aggregate` | off | Skip building `aggregate.json` (generated by default) |
| `--use-claude` | off | Use Claude API instead of local LM Studio |
| `--full-transcripts` | off | Include full transcript text in prompt |
| `--model` | `local-model` | Model name for LM Studio |
| `--claude-model` | `claude-sonnet-4-20250514` | Claude model name |
| `--lm-studio-url` | `http://localhost:1234/v1` | LM Studio API base URL |
| `--timeout` | `300` | Timeout in seconds for LM Studio API calls |
| `--force` | off | Re-process transcripts even if output already exists |
| `--self-name` | (none) | Your name as it appears in `_participants` (repeatable) |
| `--exclude-name` | (none) | Internal team member to exclude from `_account_name` (repeatable) |
| `--filter-word` | (none) | Word/phrase to strip from participant display names (repeatable) |

## Configuration files

Place any of these plain-text files in the project root to avoid repeating common CLI flags. Blank lines and `#` comments are ignored. All values are case-insensitive.

### `.self_names`

Your name(s) as they appear in `_participants`. Same as `--self-name`:

```
# .self_names
Marck
Marck Ernest
```

### `.exclude_names`

Internal team members who should never become `_account_name`. Same as `--exclude-name`:

```
# .exclude_names
Alice B.
Charlie D.
```

### `.filter_words`

Employer words or phrases to strip from participant display names. Same as `--filter-word`:

```
# .filter_words
Passion
Passion.io
```

Matches are case-insensitive and use word boundaries. Entries are applied longest-first so longer phrases (e.g. `Passion.io`) match before their substrings (e.g. `Passion`).

### Precedence

CLI flags and config files are **merged** (both apply). Config files are loaded first, then CLI flags are appended, so there is no conflict — duplicates are harmless.

All config files are gitignored by default.

## Output

Per-file JSON in the output directory:

```json
{
  "key_insights": ["..."],
  "risks": ["..."],
  "opportunities": ["..."],
  "sentiment": "positive",
  "action_items": ["..."],
  "recommended_next_steps": ["..."],
  "health_score": 7,
  "_file": "2025-05-05_Joe_and_Marck.md",
  "_account_name": "Joe",
  "_call_date": "2025-05-05 11:46 UTC",
  "_participants": ["Ben B.", "Marck Ernest"]
}
```

An `aggregate.json` is generated by default with overall stats and all call results. Use `--no-aggregate` to skip.

`_account_name` is automatically derived from `_participants`:
- Names identified by `--self-name` / `.self_names` are removed
- Internal team members (via `--exclude-name` / `.exclude_names`) are removed
- Employer words and phrases (via `--filter-word` / `.filter_words`) are stripped from remaining display names using word-boundary matching (longest-first)
- Remnants shorter than 3 characters are discarded
- The cleaned display name (case-preserved) is used as the account name

## Model-agnostic by design

This tool is built around a deliberate architectural choice: **local inference is the primary path, cloud API is the upgrade path.**

| | **Default (LM Studio)** | **Optional (--use-claude)** |
|---|---|---|
| **Cost** | Free (your hardware) | Per-token API pricing |
| **Privacy** | Fully local, no data leaves your machine | Data sent to Anthropic |
| **Speed** | Depends on hardware (GPU/VRAM) | Fast, cloud-hosted |
| **Quality** | Good (e.g., Qwen3.5 9B) | Excellent (Claude Sonnet) |
| **Rate limits** | None | API rate limits apply |
| **Volume** | Full call library | Best for curated samples |

### When to use which

- **Local LM Studio** — Daily driver. Run against your entire transcript library. No costs, no limits, no data leaving your machine.
- **Claude API** — Deep-dive on 5-10 key calls where higher analytical quality justifies the cost.

### Why this matters

No vendor lock-in. Your transcripts never leave your machine unless you explicitly opt in with `--use-claude`. Predictable costs — free at any volume on the local path.

### Model notes

**Reasoning models (e.g., Qwen3.5):** Some local models separate their output into `reasoning_content` (internal thinking) and `content` (final response). The script handles both transparently — if `content` is empty, `reasoning_content` is used as a fallback. The JSON is fully parsed regardless of which field contains it.
